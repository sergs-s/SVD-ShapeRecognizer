# SVD-ShapeRecognizer — контекст проекта для Claude Code

## О проекте

Учебное Java-приложение: распознавание рукописных геометрических фигур
(круг, треугольник, прямоугольник) методом сингулярного разложения (SVD).
Это осознанный шаг к eigenfaces — архитектура специально готовится к переходу
на распознавание лиц.

Пакет: `svd.recognizer`. GUI на Swing (NetBeans, с `.form`-файлами).

## Технологический стек

- **Java**: проект собирается под Java 26 (в NetBeans). Внимание: в системном
  PATH может быть другой JDK (например, 25) — при расхождении версий сверять
  с настройками платформы в NetBeans.
- **Сборка**: Maven (`pom.xml` в корне). Maven встроен в NetBeans, путь к нему
  добавлен в PATH.
- **OpenCV**: `org.openpnp:opencv:4.9.0-0` — НАТИВНАЯ Windows-сборка
  (`opencv_java490.dll`). Инициализация: `nu.pattern.OpenCV.loadLocally()`.
  ВАЖНО: эта .dll работает только на нативном Windows. В WSL/Linux/облаке
  она не загрузится — поэтому работать только в локальной (Local) сессии.
- **Линейная алгебра**: Apache Commons Math 3 (`SingularValueDecomposition`).
- **ОС**: Windows 11. IDE: NetBeans.
- Проект под git.

## РАБОЧИЕ ПРАВИЛА (соблюдать строго)

1. **Менять только то, что попросили.** Не трогать работающие части по своей
   инициативе. Не рефакторить «заодно».
2. **Не ломать рабочее.** Если правка рискует затронуть смежный код — сначала
   предупредить, а не делать молча.
3. **Всегда смотреть изображения в ПОЛНОМ разрешении 64×64**, а не в сжатых
   ASCII-сетках. Сжатые сетки искажают тонкие линии (линия «исчезает» или
   выглядит разорванной) и многократно приводили к ложным выводам о разрывах.
   Для SVD «лучше пара лишних точек внутри, чем разрыв контура».
4. **При работе с .form-файлами**: `.java` и `.form` должны быть синхронны
   (одинаковый набор компонентов, объявленные обработчики событий совпадают).
   Не трогать сгенерированные блоки `//GEN-BEGIN ... //GEN-END`, если не
   синхронизируешь обе стороны. Использовать именованные обработчики событий
   (NetBeans-стиль), не лямбды, в коде, привязанном к .form.
5. **Предпочитать визуальную проверку метрикам.** Если вывод алгоритма —
   изображение, смотреть на само изображение, а не только на числа.

## КЛЮЧЕВЫЕ РЕШЕНИЯ (зафиксированы, проверены на данных)

### Препроцессинг (ImagePreprocessor.java)
Конвейер: `preprocess(file, ShapeClass)` → toGrayscale → binarize →
isolateMainShape → extractROI → выравнивание по классу → renderOnCanvas →
imageToMatrix.

- **Бинаризация**: адаптивный гауссов порог (blockSize 51, C 10) для ВСЕХ
  классов + MORPH_OPEN 3×3. (Заменил Otsu — тот терял бледные грани.)
- **Выравнивание**: прямоугольник — по длинной грани (HoughLinesP, только если
  aspect ≥ 1.25) + forceLandscape; круг — без поворота; треугольник — по
  основанию.
- **MAXPOOL_DILATE_MULT = 1.2** — критический параметр. Проверено на 22 фигурах:
  1.5 + финальное смыкание + bridge давали 3 ошибки классификации (утолщение
  размывало форму); maxpool 1.0 без подпорок давал 0 ошибок, но 3 фигуры
  разваливались на куски; **1.2 без подпорок = 0 ошибок, 0 развалов** —
  оптимум. Финальное смыкание 5×5 и bridgeEndpoints УДАЛЕНЫ как вредные.
- Мелкие косметические разрывы линии допустимы — для σ-вектора почти не влияют
  (<1% пикселей).

### Распознавание — «Путь B» (ShapeRecognizer.java)
- Неизвестная фигура прогоняется через ВСЕ ТРИ ветки препроцессинга (как круг,
  как треугольник, как прямоугольник). Для каждой гипотезы считается σ-вектор
  именно той ветки и сравнивается со СРЕДНИМ σ-вектором этого класса.
- Среди гипотез, прошедших СВОЙ порог, берётся минимальное расстояние; если ни
  одна не прошла — «не распознано».
- **Три порога — по одному на класс** (масштаб расстояний у классов разный).
  Кнопки ×1.0/×1.5/×2.0 задают порог = (среднее внутриклассовое) × множитель.
  По умолчанию ×2.0 — на 22 фигурах даёт 0 ошибок, 0 «не распознано».
- Пороги сохраняются в `settings.properties` в корне проекта (SettingsStore).
- Признак — σ-вектор: топ-20 сингулярных значений матрицы 64×64,
  нормированных по σ₁ (SVDComputer).

### Обучение
- Усреднение σ-векторов класса (`TemplateStore.recalculateAverage`) —
  автоматическое при добавлении/удалении эталона. Отдельная кнопка «Обучение»
  сейчас НЕ нужна; станет осмысленной при переходе на подпространства.

### Защита от «не своего класса» при загрузке шаблонов
- НЕ делаем семантическую проверку класса при загрузке (парадокс: классификация
  без классификатора; загрузка шаблонов = обучение, эксперт определяет классы).
  Существующего флага BAD (техническое качество препроцессинга) достаточно.

## ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ σ-ВЕКТОРА (диагностированы, измерены)

- σ-вектор реагирует на «ранг/гладкость» фигуры. Идеальный Paint-квадрат
  (square7) математически вырожден (2 ненулевых σ), а рукописные — высокого
  ранга (5-6 σ). Поэтому идеальный квадрат — выброс в своём классе (расстояние
  0.627), дальше от рукописных, чем они друг от друга. Дублирование его в
  обучении НЕ помогает (убивает распознавание рукописных).
- Мусор (фото кота) → облако пикселей → классифицируется как ближайший из 3
  классов. Замкнутый классификатор без класса «отвергнуть» это не лечит.
  Порогом не отделить: кот (0.476) оказывается БЛИЖЕ к среднему квадрата, чем
  идеальный квадрат (0.627) — порядок инвертирован.
- Вывод: это фундаментальные ограничения σ-вектора, не баги препроцессинга.

## СЛЕДУЮЩИЙ ЭТАП — SVD-подпространства (eigenshapes)

Запланированный переход (мотивирован ограничениями выше). На данных доказано,
что он решает ОБЕ проблемы:
- Строить per-class базис: центрирование + SVD матрицы образцов, k ≈ 4 главных
  компоненты.
- Классифицировать по ОШИБКЕ РЕКОНСТРУКЦИИ (насколько вход вписывается в
  подпространство класса), а не по расстоянию до среднего.
- Измерено: square7 реконструируется в подпространстве квадрата с ошибкой 9.15
  (лучше некоторых рукописных), мусор даёт 18+ во всех классах — чистый зазор,
  один общий порог ~13 разделяет фигуры и мусор. Классификация: 0 ошибок на 22.
- Здесь же обретает смысл кнопка «Обучение» (построение базисов один раз).
- Это прямая дорога к eigenfaces.

## Тестовые данные
