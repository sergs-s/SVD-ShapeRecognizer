# SVD-ShapeRecognizer — контекст проекта для Claude Code

## О проекте

Учебное Java-приложение: распознавание рукописных геометрических фигур
(круг, прямоугольник, треугольник) методом сингулярного разложения (SVD).
Это осознанный шаг к eigenfaces — этап фигур закрыт, метод подпространств
реализован и испытан, идёт подготовка к переходу на распознавание лиц.

Пакет: `svd.recognizer`. GUI на Swing (NetBeans, с `.form`-файлами).

Работа с внешним программистом и заказчиком завершена, проект ведётся
самостоятельно.

## Технологический стек

- **Java**: проект собирается под Java 26 (в NetBeans). Внимание: в системном
  PATH может быть другой JDK (например, 25) — при расхождении версий сверять
  с настройками платформы в NetBeans.
- **Сборка**: Maven (`pom.xml` в корне). Maven встроен в NetBeans, путь к нему
  добавлен в PATH.
- **OpenCV**: `org.openpnp:opencv:4.9.0-0` — НАТИВНАЯ Windows-сборка
  (`opencv_java490.dll`). Инициализация: `nu.pattern.OpenCV.loadLocally()`.
  ВАЖНО: эта .dll работает только на нативном Windows.
- **Линейная алгебра**: Apache Commons Math 3 (`SingularValueDecomposition`).
- **ОС**: Windows 11. IDE: NetBeans.
- Проект под git. `master` с тегом `v1.0-sigma` (метод σ-вектора);
  рабочая ветка `svd-subspaces` (PR #2 «Eigenshapes» смержен, коммит
  `491fe2d`). Тег `v2.0-subspaces` (коммит `736dcdf`) — состояние
  подпространств до устранения технического долга. Лица ведутся на той же
  ветке `svd-subspaces` (новую не заводим, этапы отмечаются тегами);
  слияние в `master` — после этапа своей базы, по решению Хозяина.

## ТЕКУЩЕЕ СОСТОЯНИЕ (проверено по коду, ветка svd-subspaces)

Два режима распознавания, переключатель в интерфейсе (`RecognitionMode`):

- **σ-вектор** (старый, тег `v1.0-sigma`): признак — топ-20 сингулярных
  значений матрицы 64×64, нормированных по σ₁ (`SVDComputer`). «Путь B» в
  `ShapeRecognizer`: неизвестная фигура прогоняется через все три ветки
  препроцессинга, для каждой гипотезы σ-вектор сравнивается со средним
  σ-вектором класса; порог свой на класс (`threshold.CIRCLE`,
  `threshold.RECTANGLE`, `threshold.TRIANGLE` в `settings.properties`).
- **Подпространства** (текущий режим по умолчанию, `recognition.mode=SUBSPACE`
  в `settings.properties`): для каждого класса — средний вектор + первые k
  столбцов U из SVD центрированной матрицы эталонов; классификация по ошибке
  реконструкции ε = ‖x′ − B Bᵀ x′‖; единый порог θ = `subspace.threshold`
  (сейчас 15.0). Классы: `SubspaceModel`, `SubspaceTrainer`,
  `SubspaceRecognizer`, `ImageVectorizer`; `Template.normalizedMatrix`.
- Обучение подпространств только по кнопке «Обучение»; `addTemplate()`
  сбрасывает модель (`clearSubspaceModel()`).
- Параметры подпространств: k = 4 на все классы, θ = 15.0.

### Результаты тестирования (отложенный контроль, leave-one-out)

- Круги 6/7, треугольники 7/7, прямоугольники 7/12.
- Все 5 провалов прямоугольников — «не распознано» (ошибка выше порога), не
  путаница классов. Класс прямоугольников неоднороден (в основном квадраты,
  несколько вытянутых, каждая пропорция в единственном экземпляре), k = 4 не
  покрывает вариативность.
- Чужие фигуры: 3/5 в обоих режимах; при θ = 15 проходят порог 2 из 4
  не-фигур (порог подбирался перебором θ от 1 до 22 на 11 изображениях —
  7 фигур, 4 не-фигуры).

### Технический долг (закрыт, после тега `v2.0-subspaces`)

1. Дубль логики подпространств удалён из `ShapeRecognizer` (там остался
   только σ-вектор); подпространства — только `SubspaceRecognizer`.
2. θ и k по умолчанию заданы в одном месте — `SettingsStore`
   (θ = 15.0, k = 4). `SubspaceRecognizer` получает θ в конструкторе,
   спиннер θ в `MainFrame` берёт начальное значение из `SettingsStore`;
   `SubspaceTrainer.DEFAULT_K` и `train(store)` удалены.
3. `SubspaceTrainer.extractBasis`: `actualK = min(k, N − 1)`, при N < 2 —
   исключение.

Проверено: отложенный контроль (leave-one-out по 26 эталонам) до и после
правок совпал полностью — ε по всем классам для каждого изображения.

## ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ σ-ВЕКТОРА (диагностированы, измерены, актуальны для истории проекта)

- σ-вектор реагирует на «ранг/гладкость» фигуры. Идеальный Paint-квадрат
  математически вырожден (2 ненулевых σ), а рукописные — высокого ранга
  (5-6 σ). Поэтому идеальный квадрат — выброс в своём классе, дальше от
  рукописных, чем они друг от друга. Дублирование его в обучении не помогает.
- Мусор (например, фото постороннего объекта) → облако пикселей →
  классифицируется как ближайший из 3 классов. Замкнутый классификатор без
  класса «отвергнуть» это не лечит; порогом σ-вектор не отделить.
- Это фундаментальные ограничения σ-вектора, не баги препроцессинга. Метод
  подпространств решает обе проблемы через классификацию по ошибке
  реконструкции (измерено при разработке: чёткий зазор между фигурами и
  мусором).

### Принципы для лиц (зафиксированы заранее, не повторять ошибок с фигурами)

- Без whitening: не делить компоненты на σ.
- Одна нормализация освещения, не каскад из многих.
- Центрирование общим средним вектором класса, не по каждому изображению.
- Без StandardScaler на пиксельных векторах при малой выборке.
- Подпространство на каждого человека, классификация по ошибке
  реконструкции, единый порог θ.
- k подбирать по доле энергии (сумма σᵢ² первых k = 90–95 % от всей),
  отдельно для каждого класса; k ≤ N − 1.
- Набор фото на человека заранее собирать с разными ракурсами и освещением,
  а не дополнять по одному кадру после провала.
- Качество мерить отложенным контролем; автоматизировать его (одна команда,
  а не ручные клики).
- Порог подбирать по раздельным долям: пропущенные свои и принятые чужие, на
  достаточном наборе чужих.
- Единый источник конфигурации, никаких случайных стартовых моделей.
- Современный детектор лиц вместо каскадов Хаара.
- Уроки PPCA-скоринга (шаг 4б, пункт «б», отрицательный результат;
  обоснование воспроизводится `mvn compile exec:java@faces-ppca`):
  - нормировка на дисперсию остатка s², оценённую по каждому человеку
    отдельно, при 5–8 снимках вредна (FRR +23…+48 п. п.): грубая оценка s²
    переставляет людей;
  - член внутри подпространства (PPCA, whitening внутри подпространства) на
    ORL бесполезен: у чужих проекция на подпространство постороннего
    человека меньше, чем у своих;
  - полное −ln p PPCA не вырождается, но хуже ε₁/ε₂.

### Правила оценки лиц (устоявшиеся, утверждены Жориком 26.09.2026)

- Порог выбирается по критерию Неймана – Пирсона (наибольший порог, при
  котором доля принятых чужих на валидации ≤ α) на объединённой валидации
  всех фолдов. На контрольной части порог не подбирается никогда.
- FAR выводится и по попыткам, и по людям (чужой принят, если принят хотя бы
  один его снимок), каждый с точной односторонней верхней 95 % границей
  Клоппера – Пирсона (при нуле ошибок также 3/n). Граница по попыткам
  оптимистична: снимки одного человека коррелируют.
- Основной скоринг — ε₁/ε₂ (ошибка лучшего подпространства к второму), ε
  выводится рядом для сравнения. Ограничение ε₁/ε₂: оценка зависит от
  состава галереи (второй кандидат), поэтому порог калибруется заново при
  любом изменении списка людей; при галерее из одного человека скоринг не
  определён; порог, подобранный на ORL, на свою базу не переносится.
- Оценка на ORL: `mvn compile exec:java@faces-eval`, отчёт в `reports/faces/`
  (в `.gitignore`); база — путь `faces.dataset.dir` в `settings.properties`.
